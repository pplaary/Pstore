## 二、需要修复的问题（3 条）

### 问题 1：P0-4/P0-5 内部矛盾 — §6.1 vs §6.2 的 tokenize 行为不一致 🔴

**发现方**：Claude  
**位置**：§6.1（分词函数定义）→ §6.2（FTS5 转义示例）

**矛盾点**：
- §6.1 定义：连续非 CJK 字符合并为一个 token
- §6.2 示例：`(550ml)` → tokenize → `"( 550ml )"`（拆成了三个 token）

输入 `(550ml)` 全是非 CJK 字符且相邻，按 §6.1 规则应保持为一个 token `(550ml)`。但 §6.2 给了拆分的示例，直接违反自己的定义。Agent 实现时会不知道该信哪个。

**建议修复**：删除 §6.2 中拆分式转义示例，改为——tokenize 保持 §6.1 规则（单 token），转义规则简化为「该 token 含特殊字符时整体用一对双引号包裹」，如 `"(550ml)"`。

---

### 问题 2：P1-4 散装标签存储方案生产不可行 🔴

**发现方**：Claude  
**位置**：§12.5  
**严重性**：Claude 建议从 P1 提级为 P0

**问题**：规格要求散装标签写入 `src/config/looseGoodsLabels.ts` 编译时常量，管理模式增删改通过编辑文件 + 热重载生效。但真机 APK 没有 Metro 开发服务器，不存在文件热重载能力。

**后果**：用户管理模式中编辑散装标签后，APK 上完全不会生效——功能实质性失效。

**建议修复**：改为运行时本地存储。方案二选一：
- SQLite 单表：`CREATE TABLE loose_goods_labels (id INTEGER PRIMARY KEY, label TEXT, sort_order INTEGER)`
- AsyncStorage JSON：`AsyncStorage.setItem('looseGoodsLabels', JSON.stringify(labels))`

---

### 问题 3：P0-5 FTS5 转义中 `*` 通配符处理不当 🟡

**发现方**：Gemini  
**位置**：§6.2 FTS5 查询特殊字符转义

**问题**：当前转义规则将 `*` 也列入转义范围并用双引号包裹（`"*"`），但 `*` 在 FTS5 中是前缀查询通配符，包裹后失去通配功能，无法匹配前缀搜索。

**正确语法**：`"可" "乐"*`，`*` 紧跟在双引号右侧外部。

**建议修复**：在转义规则中将 `*` 从「需转义的特殊字符」列表中移除，或单独说明：`*` 仅当作为前缀通配符时保留在双引号外，非末尾 `*` 仍转义。
